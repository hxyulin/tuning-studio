# Tuning Studio 0.1.3

This release rebuilds the VS Code panel and fixes symbol resolution in LTO builds.

## VS Code panel

- One panel holds Live Watch on the left and the plot on the right, with a draggable divider.
  The toolbar opens the firmware ELF, connects, selects a 2, 5, 10 or 30 s window, pauses the
  plot and records to `.tuning-studio/recordings/`.
- A Tasks group lists each Embassy task with its current state. Expanding a task shows the
  locals held at that suspend point, which can be plotted like statics.
- The filter also matches members already loaded under a static or a task.
- Legend names drop the task pool path, and the y-axis sizes itself to its widest label.
- Connect and session failures are written to the Output channel.

## Symbols

- Types first referenced by global offset (`DW_FORM_ref_addr`) now resolve. Before, some
  types in LTO builds stayed unresolved placeholders.
- Members that rustc duplicates in async suspend states are listed once.
- Vtables, metadata sections, RTT buffers and zero-sized statics are hidden.

## Other changes

- Dependencies are at their latest versions, including gimli 0.34 and object 0.40. The
  extension requires VS Code 1.140 or later.
- Backend calls give up after 60 s, except dialogs and CSV export.

Sampling never halts the core. Opening and closing a probe session each halt it for about
20 ms while probe-rs clears hardware breakpoints, measured on an STM32H723.
